uv crash course

Fast alternative to venv, poetry and co.

§0 · uv

Why uv?

One fast tool for environments + packages + Python itself.

  • 10–100× faster than pip — fast enough to rebuild an environment per job
  • One tool where you had pip, pip-tools, pipx, poetry, pyenv, virtualenv
  • uv.lock — same environment on every machine
  • It installs Python interpreters too: uv python install 3.12

Install: docs.astral.sh/uv/getting-started/installation · speed figure: Astral’s benchmark, warm cache. For a paper, commit pyproject.toml and uv.lock.

§0 · uv

The commands you need


uv init myproject         # new project: pyproject.toml, .python-version, git
uv sync                   # make .venv match uv.lock exactly
uv add numpy              # add a dependency: pyproject + lock + .venv
uv run pytest             # run inside the project environment
uv run scripts/plot.py    # for a .py file, the word "python" is optional
uvx ruff check .          # run a tool in a throwaway environment

Everything today runs through uv run.

§0 · uv

Keep the cache on the same filesystem

Installing links a package out of one global cache into your .venv — and a link cannot cross filesystems.

warning: Failed to hardlink files; falling back to full copy.
This may lead to degraded performance.

Cache in $HOME, project on /data — uv copies every file. Give each mount its own cache with direnv:


# /data/<user>/.envrc          → and the same under /work, /tikhome
export UV_CACHE_DIR=/data/$USER/uv-cache

On a cluster, prefer the site Python where MPI and BLAS are tuned: --no-managed-python. If inodes are tight, UV_PROJECT_ENVIRONMENT moves the venv to scratch.

§1

The agent loop

§1 · The agent loop

What makes it “agentic”?

You set the goal. The model plans, then runs its own loop:

  • act — read and write files, run commands, run tests
  • observe — errors, test results, diffs
  • revise — adjust and go again, until the goal is met
  • goal
  • plan
  • act
  • observe
  • revise

§1 · The agent loop

The one skill: find the divergence

You say what you want built. The agent forms its own plan. Your job is to find where the two come apart — and which gaps matter.

It reaches for pytest; you write unittest

Same result, different taste.Align with it. Move on.

You want the analytic solution; it plans a neural network

Different science.Catch it in the plan, before any code.

Spend your attention on the divergences that change the result.

Autonomous runs call this implementation drift: the agent quietly substitutes an approach it finds easier. Trehan & Chopra, arXiv:2601.03315 (2026).

§1 · The agent loop

When to delegate

Agents shine on small, well-specified tasks. They can struggle where architectural judgement is needed.

✓ Delegate

“Add an RK4 step and test its convergence order.”

✗ Decide yourself

“Redesign how the solver handles stiff systems.”

Today’s task is deliberately small.

§4 · Steering the agent

Three kinds of memory

~/.claude/CLAUDE.md

User memory. Every project, every session. How you work.

./CLAUDE.md

Project memory. This repo, shared with the team through git.

~/.claude/projects/

Auto memory. Claude’s own notes on your project. On by default, machine-local.

The first two are instructions you write. User memory costs tokens in every session — a real one:

All Python projects use uv!
Docstrings must follow numpy style!
Never modify tests marked @pytest.mark.protected without explicit approval!
GH issues and PRs must include p-<x> priority and effort-<x> labels.
New features must start in a branch or git worktree.
Explicit Error > User Warning > Silent Failure > Crash.

/memory lists and opens all of them.

§4 · Steering the agent

CLAUDE.md — project memory

Instructions Claude reads every session: conventions, how to run things, gotchas. Loaded in full, however long it is — so keep it short.

The concision test

For each line ask: “would removing this cause a mistake?” If not — cut it.

Bloated CLAUDE.md files get ignored.

It is context, not enforcement. To make something impossible rather than requested, use a hook (§7).

§4 · Steering the agent

Skills — instructions on demand

CLAUDE.md is always loaded. A skill loads only when its description matches.

.claude/skills/decay-plots/SKILL.md


---
name: decay-plots
description: Plot solver output against the analytic solution.
             Use when making figures from odelab results.
---

Use matplotlib. Put the error on a log axis.
Label every axis with units. Save to figures/ as PDF.

The description says when to use it. Write it as “use when…”.

§5 · Ship a feature

The task: add RK4

Add a 4th-order Runge–Kutta step alongside Euler — and prove it is better.

One branch

Open add-rk4 before any code lands.

Two commits

The failing test first, then the code that makes it pass.

The canonical loop is Explore → Plan → Implement → Commit; test-first is our addition.

§5 · Ship a feature

Say it precisely

Precise

“Add an rk4_step to odelab/integrators.py, used through integrate(..., method=...), and assert convergence order 4 the way test_euler_is_first_order does.”One reading. Nothing left to invent.

Vague

“Fix the integrator.”
“Write some tests.”
“Make it more accurate.”The agent guesses scope, place and approach.

Reduce what the agent has to assume: which file, which function, what is wrong, how you want it fixed.

Two reviewers: the agent, and you. Both read the whole branch.

Merge only what you have read.

§6 · Failure patterns

Five ways it goes wrong — and the fix

Kitchen-sink session

/clear between unrelated tasks

Correcting over and over

After two tries: /clear and a better prompt

Over-specified CLAUDE.md

Prune ruthlessly

Trust-then-verify gap

Always give a check. Cannot verify → do not ship

Infinite exploration

Autonomous runs fail the same ways: overexcitement (declaring success on a failure), implementation drift, context degradation. Trehan & Chopra, arXiv:2601.03315 · taxonomy: Cemri et al., arXiv:2503.13657.

§6 · Failure patterns

Why two of those are the same bug

Everything the agent reads — your files, test output, its own reasoning — sits in one finite window.

  0%|░░░░░░░░░░░░░░░░░░░░| fresh session
 80%|████████████████░░░░| explore · plan · edits · test output
100%|████████████████████| full → /compact
 20%|████░░░░░░░░░░░░░░░░| summarised — the detail is gone

  • /context — what is filling it, including your CLAUDE.md
  • /clear between unrelated tasks · /compact to keep going through one
  • Write it to disk. A plan file survives compaction; a subagent keeps its reading out of your window

§7 · Beyond the basics

Subagents and hooks

Subagents

A scoped task in its own context. Its reading stays out of your window.

Hooks

Deterministic automation on events. This one runs the suite after every edit:

.claude/settings.json


{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command", "command": "uv run pytest -q" } ] }
    ]
  }
}

§7 · Beyond the basics

MCP — hand the agent a new tool

One protocol between agents and tools. Anthropic published it in 2024; the other vendors adopted it.


import subprocess
from fastmcp import FastMCP

mcp = FastMCP("cluster")

@mcp.tool
def job_status(job_id: str) -> str:
    """State of a SLURM job. Use when asked whether a run finished."""
    return subprocess.check_output(["squeue", "-j", job_id], text=True)
  • The type hints tell the agent what to pass
  • The docstring tells it when to call — the same lesson as a skill’s description

Try Context7 first: current library docs, so the agent stops guessing APIs.
